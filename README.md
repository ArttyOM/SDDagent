# Сбор системной аналитики через CLI

Локальное веб-приложение для сбора входных данных и запуска аналитики через `codex` или `gigacode`.

## Запуск

```bash
npm start
```

Windows без установленного глобально Node.js:

```bat
start.cmd
```

Linux:

```bash
chmod +x start.sh
./start.sh
```

По умолчанию приложение открывается на `http://127.0.0.1:5178`.

## Конфигурация

Основные настройки лежат в `config.json`; для публикации в репозиторий добавлен безопасный шаблон `config.example.json`. Если `config.json` отсутствует, приложение использует значения из примера.

Важные поля:

- `cli.active` выбирает, какой CLI использовать: `codex` или `gigacode`.
- `cli.commands.codex` и `cli.commands.gigacode` задают команду, аргументы, рабочую папку и способ передачи prompt.
- `service.mode` задает режим работы с репозиториями: `local` для локально развернутого сервиса или `global` для работы через URL репозитория.
- `service.defaultBranch` задает ветку по умолчанию для глобального режима; если пользователь не указал ветку, используется `main`.
- `service.repositoryCheckoutDirectory` задает каталог, куда сервер скачивает репозитории в глобальном режиме.
- `integrations.jira.baseUrl` и `integrations.confluence.baseUrl` задают адреса систем.
- `integrations.jira.authMode: "browser"` и `integrations.confluence.authMode: "browser"` включают браузерную аутентификацию: приложение открывает стабильную стартовую страницу `baseUrl` + `browserAuthPath`, а выбор клиентского сертификата показывает браузер/ОС. Готовые IdP-ссылки со `state` и `nonce` хранить не нужно: они динамические.
- `certificate.pfxPath` или пара `certificate.certPath` + `certificate.keyPath` задают клиентский сертификат для серверной проверки, если для интеграции используется `authMode: "certificate"`.
- `certificate.passphraseEnv` задает имя переменной окружения с паролем к сертификату для серверной проверки.
- `outputDirectory` задает каталог, куда CLI должен сохранить markdown-аналитику.

## Что делает приложение

- Показывает CLI, выбранный в `config.json`, и запускает только его.
- Управляет списком путей к репозиториям и их назначением.
- Загружает несколько файлов системной аналитики с любыми расширениями.
- Открывает браузерную аутентификацию Jira и Confluence с системным выбором клиентского сертификата и при необходимости проверяет серверные интеграции через сертификат из конфигурации.
- Собирает ссылки на задачи Jira и страницы Confluence.
- Запускает выбранный CLI по каждому заполненному блоку, затем запускает финальный запрос на создание структуры markdown-файлов.
- Показывает stdout/stderr CLI в браузере и позволяет отправлять текст в активный CLI-процесс, если выбранная команда оставляет stdin открытым.

## Режимы работы с репозиториями

В `service.mode: "local"` кнопка выбора папки открывает системный диалог на сервере и передает в задачу абсолютный путь к выбранной папке. Файлы репозитория через браузер не загружаются.

В `service.mode: "global"` пользователь указывает URL репозитория, ветку и, если нужно, данные аутентификации. Перед запуском CLI сервер выполняет `git clone` указанной ветки в `service.repositoryCheckoutDirectory`, а агент получает локальный путь к скачанным файлам.
